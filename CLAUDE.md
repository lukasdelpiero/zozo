# ZoZo — instruções para o Claude Code

Aplicativo de finanças pessoais: trate toda mudança como sensível a segurança.
O padrão obrigatório está em @docs/SEGURANCA.md — leia antes de mexer em login, sessão, API, banco, criptografia, exportação ou configuração do Cloudflare.

## Regras que mais se aplicam a este código

- **Criptografia de ponta a ponta**: o servidor só vê documentos cifrados (AES-256-GCM no navegador). Nunca envie dados legíveis nem a senha à API. Não mude as derivações em `ui/js/bridge/host-web.ts` (`zozo/dados/v2`, `zozo/prova/v2`, AAD) sem uma migração: documentos já gravados deixariam de abrir. Contas antigas (PBKDF2) viram Argon2id no primeiro login (`migrarParaArgon2` → `PUT /api/conta/kdf`, documento e histórico recifrados numa transação; histórico que não cabe num pedido vai antes em etapas por `PUT /api/conta/kdf/historico`, tabela `kdf_etapas`). Nunca descarte cópias do histórico para conseguir migrar.
- **Recuperação de senha (exceção deliberada ao ponta a ponta, escolhida pelo dono do produto)**: por padrão o navegador guarda no servidor uma cópia da chave dos dados (tabela `custodia`), trancada no navegador com uma chave que só o servidor calcula (HMAC do `SEGREDO`, rótulo `zozo/custodia/v1`). "Esqueci minha senha" (`/api/recuperacao/*`: link de 1 h + código do 2FA, se houver) devolve essa chave e a cópia; o navegador recifra tudo com a senha nova. Quem tem o banco **e** o `SEGREDO` consegue abrir os dados dessas contas. **Proteção avançada** (Configurações › Conta) apaga a cópia: só a pessoa abre os dados e, esquecida a senha, a conta recomeça vazia. Toda troca de chave (senha, migração, recuperação) apaga a cópia antiga e o navegador guarda a nova.
- **Identidade vem da sessão** (cookie HttpOnly), nunca do corpo do pedido. Rotas de dados exigem sessão **e** a prova da senha (`X-ZoZo-Prova`).
- **Banco**: só comandos parametrizados. Mudança de tabela = novo arquivo em `api/migracoes/NNNN_nome.sql` (nunca edite uma migração já aplicada).
- **Segredos** (`SEGREDO`, `TURNSTILE_SECRET`, `RESEND_API_KEY`) só por `npx wrangler secret put`; nunca no `wrangler.toml`, no código ou em logs.
- **Interface**: sem `innerHTML`/`eval`; todo DOM via `ZoZo.dom` (`h`, `s`). CSP sem scripts/estilos inline.
- **Logs**: só eventos (`ctx.evento`), sem e-mail, IP, senha, prova, cookie ou código 2FA em texto.
- **Testes**: todo controle de segurança novo precisa de teste negativo em `api/tests/test_api.py`.

## Comandos

- Testes da API: `cd api; uv run python -m unittest discover -s tests -v` (inclui o app FastAPI; com `python` puro os testes do FastAPI são pulados) · Tipos do back-end: `cd api; uv run mypy` (modo estrito em `api/src`; mudou uma função, anote parâmetros e retorno — `Banco`/`Servicos`/`Config` em `nucleo.py`)
- Testes do serviço de dados e do host web (criptografia, API falsa): `npm test` · Tipos: `npm run typecheck`
- Interface com recarga instantânea: `npm run dev` → http://127.0.0.1:5173 (com a API local; sem servidor: Modo teste › simular cadastro e login)
- API local + interface montada: `npm run build` e `python api/dev/servidor_local.py` → http://127.0.0.1:8787
- Interface: Vite + TypeScript + Tailwind CSS (prefixo `tw:`, sem preflight). O CSS que sobrou (camada `legado`) é de propósito: `css/tokens.css` (variáveis), `css/base.css` (fontes, reset, foco, dinheiro, estados globais, lista aberta do select), `css/movimento.css` (animações por posição dos filhos) e `css/print.css` (impressão da fatura); componente novo vai em Tailwind. Migre uma tela por vez; módulo convertido = `.ts` + tipo em `ui/src/globais.d.ts`. Já migrados: Configurações › Sobre, o login (`components/auth.ts`), Transações (`pages/lancamentos.ts` + `LaunchRow`) Categorias (`pages/categorias.ts` + `CategoryRow`/`CategoryGroupRow`), Contas (`pages/contas.ts` + `AccountRow`), Dashboard (`pages/dashboard.ts`), a estrutura — menu lateral, barra superior, painel, menus flutuantes e janelas modais (classes em `components/estrutura.ts`; `menu`, `modal`, `modal--x`, `detail`, `main` ficam como ganchos) — e as peças compartilhadas + conteúdo dos painéis + gráficos (classes em `components/pecas.ts`; `line-chart`, `line-chart__svg`, `donut`, `inline-input`, `icon-pick`, `lp-chip-btn`, `lp-props`, `lp-notes-wrap`, `lp-name`, `lp-value`, `pl` ficam como ganchos), Recorrências (`RecurrenceRow`, título `tipo-select`, janela de frequência), Investimentos (`pages/investimentos.ts` + `AllocationRow`), o formulário do painel (`components/forms.ts`), Perfis e Configurações (`pages/perfil.ts`; linhas das Configurações em `pecas.cfg*`, variantes `ate700`, `area560`, `area480`), Fatura (`pages/boleto.ts`; ganchos da impressão em `css/print.css` — regra de impressão que disputa com classe `tw:` precisa de `!important`), Divisão (`components/dividir.ts`), Calendário e Câmbio. Base de componente com a variante `tw:base:` (especificidade zero: a classe de quem usa vence sem `!`). Ganchos usados em variantes arbitrárias (`[&_.x]`) levam hífen, não `__` (o `_` vira espaço). Orçamento desligado: variante `tw:sem-orcamento`. Colunas por largura da área: variantes `tw:area620/460/420/340` (container queries). Classes `tw:` sempre escritas por inteiro (nada de montar o nome); ao migrar, confira o resultado comparando estilos calculados antes/depois.
- TypeScript: toda a interface é `.ts` (`allowJs: false`). O serviço de dados (`data/servico.ts`) tipa o documento cifrado (`Documento`, `Lancamento`, `Conta`…; `any` só na leitura dos dados brutos, antes de conferir) e tem os testes em `ui/tests/servico*.test.mjs`. O host web (`bridge/host-web.ts`) tem os testes em `ui/tests/host-web.test.mjs`: derivação das chaves e formato do documento conferidos com uma implementação independente. Os tipos dos dados (documento e respostas do serviço) ficam em `ui/src/dados.d.ts`: o serviço é conferido contra eles (`LEITURAS` devolve `RespostasLeitura[ação]`) e as telas os recebem por `ctx.loadData` / `ctx.bridge.request`; mudou o que o serviço devolve, mude lá. Depois do `estadoCarregamento`, leia os dados com `C.carregado(state, chave)`. Telas já sem `any`: Transações e o painel da transação, Recorrências, Investimentos, Contas, Dashboard, Categorias, Perfis e Configurações, Fatura, janelas, divisão e todos os componentes (login, app, câmbio, gráficos, lista, painel de testes). Toda ação tem a resposta tipada (`RespostaDe<ação>`: `RespostasLeitura`, `RespostasEscrita` — conferidas no serviço — e `RespostasHost` — conferidas em `host-web.ts`). `any` só onde é de propósito: leitura de dados brutos (serviço e `RespostaApi` do host) e os dados de demonstração. Regra nova de dinheiro = ação no serviço (atômica, conferida lá, com teste negativo), nunca só na tela. Módulo usado nos testes (`ui/tests/carregar.mjs`) entra em TS pela lista `MODULOS` (tipos removidos com `stripTypeScriptTypes`).
- Listas longas (Transações): o que só muda algumas linhas (item aberto, caixas marcadas) vai em `depsLinhas` + `atualizarLinhas` da página (o roteador troca essas linhas no lugar, sem redesenhar milhares de itens); meses com `content-visibility: auto`. O roteador devolve o foco depois de redesenhar pelo `data-fk` ou, em botões de linha, pelo `data-id` (teste em `ui/tests/router.test.mjs`). Última auditoria do frontend: `docs/AUDITORIA-FRONTEND.md`; do back-end (ASVS 5.0 nível 2): `docs/AUDITORIA-BACKEND.md`.
- Busca: local, em `ui/js/core/busca.ts` (os dados são cifrados de ponta a ponta — nunca use um servidor de busca como Meilisearch/Algolia, que exigiria os dados legíveis fora do navegador).
- E-mail no servidor local: `ZOZO_DEV_EMAIL=console` (mostra os e-mails no terminal) e `ZOZO_DEV_BANCO=<arquivo>` (banco descartável).
- Back-end: FastAPI + Pydantic em `api/src/app_fastapi.py` na frente do núcleo, que continua dono das regras. Ligado só na prévia (`API_FASTAPI = "1"` em `[env.previa.vars]`); produção depois de aprovado lá. Rota nova com corpo JSON = modelo estrito em `MODELOS`. Versões do `[project].dependencies` precisam existir para o Pyodide do Worker (pydantic-core compilado: confira com `uv run pywrangler sync`).
- **Modo teste** (só no endereço local e na prévia — decidido pelo endereço em `host-web.ts`, `HOSTS_PREVIA`): botão "Modo teste" com o painel (`components/teste.ts`: abre qualquer tela, etapa da entrada, painel lateral e modo de edição, janela e passo, menu, gráfico e a galeria de componentes — ao criar uma tela/janela nova, inclua-a lá), conta simulada sem servidor (só na memória da aba) e a demo com todos os recursos e ações de conta simuladas. Em produção `ZoZo.testeHost` não existe; o servidor continua recusando qualquer gravação da demo.
- Acessibilidade: WCAG 2.2 AA conferida com axe-core em todas as telas (desktop e celular). Texto que informa ≥ 4,5:1 (tokens `--color-text-secondary/muted`, cores das etiquetas `color-mix(…55%,black)`) — **exceção por escolha do produto**: o cinza `--color-text-cinza` (#7f8ba4), as pílulas de variação, o vermelho dos menus e o botão vermelho usam as cores pedidas, abaixo de 4,5:1 (não "corrija" sem pedir); nome acessível começa pelo texto visível (WCAG 2.5.3); nada interativo dentro de botão; `<button>` não contém título nem bloco.
- **Páginas públicas** (estáticas, sem JavaScript, entradas extras do Vite): apresentação `ui/sobre.html` em `/sobre` (é a "página inicial do app" informada ao Google), `ui/politica-privacidade.html` em `/politica-privacidade` e `ui/termos-uso.html` em `/termos-uso`: ao mudar o que o ZoZo guarda, por quanto tempo, com quais fornecedores, preço ou regras do serviço, atualize a página e a data.
- Backup e restauração do banco: `docs/RESTAURACAO.md` (export + `api/dev/conferir_backup.py`; nunca ensaiar restauração por cima do banco de usuários)
- **Novidades da versão** (janela "O que há de novo no ZoZo", `components/novidades.ts`): a cada versão publicada, suba `ZoZo.sobre.versao` (`config/regras.ts`, e o `package.json`) e acrescente a versão no início de `ui/js/config/novidades.ts` (ícone, título, `novo`/`melhoria`/`correcao` e uma frase do que a pessoa nota, em tom de conversa, falando com "você", sem travessões, dois-pontos nem jargão). Aparece uma vez por versão, depois de entrar; conta nova não vê; reabre em Configurações › Sobre.
- Painel da conta: `getExtratoConta` no serviço (cartão = fatura aberta: fatura anterior + lançamentos = fatura atual, compra positiva, pagamento e estorno negativos; outras contas = mês atual; nada futuro). Painéis listam o mês atual, nunca "as N mais novas" (as parcelas futuras ocupavam as vagas).
- Ciclo do cartão (`faixaDoCartao`): do dia seguinte ao fechamento anterior até o dia do fechamento, inclusive (devolve `[inicio, fim)` com `fim` = dia seguinte ao fechamento). Fatura gerada (`getBoletoData`/`cobrancaDoMes`): só cartão de crédito; perfil ou `"todos"`, cartão ou `"todos"`; com Todos ou um cartão é consulta (sem ajustes, recebidos, saldo anterior e Pix).
- Pagamento de fatura = tipo `"fatura"`, só criado por `pagarFatura`: par com `pagamento: { grupo, lado: "pagante" | "cartao" }`. O lado do cartão não sai em `getLancamentos`; editar o do pagante atualiza o par (`editarPagamentoFatura`); excluir um lado exclui os dois (`comOsPares`). Fora de gasto, orçamento e cobrança de perfil. Pares antigos (Débito + Receita com `pagamentoCartao`) são convertidos ao abrir (`converterPagamentosAntigos`).
- Publicar na **prévia** (testes): `.\api\publicar.ps1 previa`
- Publicar em **produção**: `.\api\publicar.ps1 producao` (só depois de testar na prévia)
